# 浏览器与打印机验收（v0.2）

在创建发布标签前，维护者必须在当前稳定桌面版 Chrome 和 Edge 各完成一次本清单。自动化测试无法替代真实浏览器、打印机驱动、纸张和设备不可打印边距的验证。

## 验收前准备

- 运行 `npm ci` 与 `npm run verify`，保存命令输出或 CI 链接。
- 准备一台代表性物理打印机；系统 PDF 打印机只能辅助检查分页，不能替代纸张校准。
- 使用起始模板和已脱敏的运行时 JSON，不得使用真实业务数据。
- 在两个浏览器中均使用 100%/实际大小、关闭浏览器页眉页脚，并在打印机驱动中选择模板对应的纸张。

## 每个浏览器必须验证的场景

- 创建、保存、重开、导入和导出模板；确认纸张、方向、边距和背景能完整往返。
- 输入嵌套运行时 JSON；确认文本、图片、条码、二维码、表格和标签网格均可按路径解析，且不会回退为示例业务数据。
- 配置非默认纸张；确认系统打印预览接收到相同的 `@page` 尺寸，再检查驱动设置。
- 确认越过配置安全区、缺少绑定值、空条码/二维码或不可用图片会在默认严格模式下阻止打印。
- 确认 `{ allowIncomplete: true }` 只在明确配置时允许不完整内容，并且打印页不会出现 `Unbound`、`Missing` 或任何编辑器占位文字。
- 确认长表格只重复标记了 `repeatPerPage` 的元素；较短的并列表格不会在后续页出现空表格。
- 确认原生打印预览和物理纸张中均没有编辑器工具栏、选中框、按钮或控制面板。
- 使用至少一个包含条码、二维码和远程/本地图片的模板；确认资源完全加载、机器码可扫描且文字没有被裁切。
- 记录浏览器版本、操作系统、打印机型号、纸张、驱动缩放和为设备不可打印边距做出的任何调整。

## 通过与阻塞条件

仅当 Chrome、Edge 和代表性物理打印机的全部适用场景都通过时，才可以创建发布标签。

以下任一情况均为发布阻塞：纸张尺寸或缩放错误、资源缺失、分页或重复元素错误、可扫描码不可读、内容被裁切，或输出包含编辑器/占位内容。记录浏览器与驱动版本、模板、脱敏数据和复现步骤；修复后重新执行受影响浏览器的全部场景。
